对比实验：多源RAG的「RRF融合」vs「直接拼接」

Retail RAG · 商品目录(9288) + 退货政策(8) · 数据基于预计算嵌入缓存，可复现

实验目的

项目有两个独立向量集合：商品目录 catalog_chunks（9288条）与政策 policies（8条）。查询时两种策略都会对每个源取 top-k，区别在组合方式：

  • 直接拼接（PLAIN）：按源顺序拼接，先目录后政策，去重保留先出现的。
  • RRF 融合：按倒数排名融合 score = Σ 1/(rank + K)，跨源重排并去重。

实验二：弱源（政策）是否被正确提升

数据量悬殊(9288 vs 8)下，直接拼接会让政策被商品完全淹没——所有 top-5 都是商品。而 RRF 通过"政策源内排名"信号，把相关性文档跨源提升。

查询PLAIN top5来源RRF top5来源政策首次出现位次(plain→rrf)

milk（纯商品）C·C·C·C·CC·P·C·P·C无 → 2
核心发现：商品目录(9288条)主导时，直接拼接让政策命中在 top-5 里出现 0 次；RRF 把相关政策稳定提升到第 2 位（如退货期限、生鲜不退货、免费配送门槛），且不破坏商品主导排序——弱源高相关信号不再被淹没。

  [P] Return policy: Unopened items can be returned within 30 days...

结论与使用价值

  • ✔ 多源不均衡时 RRF 保留弱源证据，直接拼接会丢失。
  • ✔ Top-3 相关命中率提升 3/12，在商品主导场景下仍有效。
  • ✔ 不劣化主导源（#1 与 PLAIN 全一致）。
  • ⚠ 局限：当跨源无高相关文档（如纯商品词 "organic avocado"），两者几乎等价——RRF 的优势集中在跨知识源语义重叠的查询上。
